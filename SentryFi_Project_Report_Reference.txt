   CHAPTER 1: INTRODUCTION AND PROBLEM STATEMENT

1.1 Background: AI in Financial Security
-----------------------------------------
The global financial system faces escalating threats from cybercriminals,
fraudulent invoicing, phishing attacks, and regulatory non-compliance.
According to cybersecurity reports, phishing attacks account for over 36% of
all data breaches, and invoice fraud alone costs global enterprises billions
of dollars annually. Anti-Money Laundering (AML) violations and SOX
(Sarbanes-Oxley Act) compliance failures further expose organizations to
regulatory sanctions and reputational damage.

Traditional rule-based detection systems are insufficient against the
increasingly sophisticated and adaptive nature of financial threats. Machine
Learning offers a paradigm shift by enabling pattern recognition at scale,
anomaly detection in structured data, and natural language understanding of
regulatory documents -- all without the need for exhaustive manual rule sets.

1.2 Core Problem Areas Addressed
----------------------------------
SentryFi addresses three distinct and critical financial security domains:

  (a) PHISHING URL DETECTION
      Financial phishing attacks direct victims to spoofed websites mimicking
      banks, payment platforms (PayPal, Chase, Wells Fargo), and crypto
      exchanges. Attackers use suspicious TLDs (.xyz, .top, .ru, .tk),
      obfuscated domains, and embedded financial keywords to build deceptive
      URLs. A trained classifier can structurally analyze URLs before a user
      visits them.

  (b) INVOICE FRAUD / ANOMALY DETECTION
      Invoice tampering involves manipulating line-item totals, applying
      unauthorized tax rates, or creating fictitious invoices. Statistical
      anomaly detection using Isolation Forest can identify invoices whose
      numerical patterns deviate significantly from the normal financial
      distribution of legitimate documents.

  (c) REGULATORY COMPLIANCE VIOLATIONS
      Financial documents including contracts, payment memos, and audit
      reports often contain clauses that violate AML guidelines, SOX controls,
      or standard payment terms. NLP-based text classification can
      automatically flag these violations at a clause level for human review.

1.3 Objectives of SentryFi
----------------------------
  1. Build and train three domain-specific ML models for financial threat
     detection.
  2. Expose the models through a REST API using FastAPI with OCR document
     processing.
  3. Create a professional, production-grade React dashboard enabling
     real-time scanning and audit trail management.
  4. Integrate Firebase Authentication and Firestore for secure user
     management and persistent scan history.
  5. Deploy the system with graceful fallback mechanisms to ensure reliability
     even when cloud services are unavailable.

2.1 High-Level Architecture (Descriptive)
------------------------------------------

  [User Browser]
       |
       | HTTPS
       v
  [React 18 + Vite SPA - Vercel]
       |
       |--- Firebase Auth (Google / Email-Password)
       |--- Firestore (Scan Audit Trail)
       |--- Firebase Storage (File Storage - blob fallback active)
       |
       | REST API (Axios, 30s timeout, auto-retry on 5xx)
       v
  [FastAPI Python Backend - Uvicorn]
       |
       |--- /api/v1/scan/phishing  --> [phishing_model.joblib]
       |--- /api/v1/scan/invoice   --> [invoice_model.joblib] + OCR pipeline
       |--- /api/v1/scan/compliance --> [compliance_model.joblib]
       |--- /api/v1/health
       |
       v
  [ML Models (scikit-learn, serialized via joblib)]
  phishing_model.joblib   (105 KB) - Random Forest Pipeline
  invoice_model.joblib    (854 KB) - Isolation Forest
  compliance_model.joblib  (29 KB) - TF-IDF + Logistic Regression Pipeline

2.2 Technology Stack Summary
------------------------------
  Layer           | Technology
  ----------------+--------------------------------------------------
  Frontend        | React 18, Vite 5, React Router v6, TailwindCSS 3
  State/Auth      | Firebase 10 (Auth + Firestore + Storage)
  Charts          | Recharts 2
  Icons           | Lucide React
  HTTP Client     | Axios 1.6 (with retry interceptor)
  Backend         | Python 3, FastAPI, Uvicorn ASGI

  Model Store     | joblib (.joblib files)
  Deployment      | Vercel (frontend), env-configured backend URL

2.3 Frontend-Backend Communication Design
------------------------------------------
  - The API client (src/services/apiClient.js) creates an Axios instance
    targeting VITE_API_BASE_URL (environment variable) or falls back to '/api'.
  - A response interceptor automatically retries requests on HTTP 502/503/504,
    accommodating ML model cold starts with a 2-second delay before retry.
  - All scan results are posted to the FastAPI backend via multipart/form-data
    (file uploads) or JSON (URL scans).
  - After receiving ML results, the frontend writes a scan record to Firestore
    via firestoreService.js, with a localStorage fallback if Firestore fails.

  |
  |-- context/
  |   |-- AuthContext.jsx
  |   |   React Context and Provider for authentication state. Wraps the
  |   |   application and exposes: currentUser, loading, login(),

  |   |   to reactively update auth state.
  |   |
  |   |-- ProtectedRoute.jsx
  |       Higher-Order Component. Checks currentUser after auth loading

  |   |   Axios instance configured with:
  |   |   - baseURL: VITE_API_BASE_URL or '/api'

  |   |   changes to real-time listeners when Firestore is unavailable.
  |   |
  |   |-- storageService.js
  |       File upload service. Currently uses local blob URL as primary
  |       strategy (URL.createObjectURL) to avoid Firebase Storage CORS

3.3 Backend Source Tree (backend/)
------------------------------------

  backend/
  |-- main.py
  |   FastAPI application entry point. Defines all API routes and Pydantic
  |   request/response models. Adds CORS middleware. Uses lifespan context
  |   manager to call registry.load_models() at startup.
  |
  |-- requirements.txt
  |   Python package dependency list (18 packages).
  |
  |-- .env.example
  |   Sample environment variable file documenting PORT, ENVIRONMENT,
  |   and ALLOWED_ORIGINS configuration.
  |
  |-- core/
  |   |-- model_loader.py
  |       Defines ModelRegistry class with load_models() method. Loads
  |       phishing_model.joblib, invoice_model.joblib, compliance_model.joblib
  |       from backend/models/ using joblib. Patches sys.path and __main__
  |       namespace to resolve URLFeatureExtractor deserialization. Exports
  |       singleton 'registry' instance.
  |
  |-- services/
  |   |-- ocr_service.py
  |       process_invoice_file(file_bytes, filename) -> dict
  |       Handles PDF (pdfplumber), image (pytesseract+Pillow), and TXT input.
  |       parse_invoice_text(text) -> dict extracts four numerical features:
  |       tax_to_subtotal_ratio, line_item_sum_delta, round_amount_score,
  |       amount_z_score via regex pattern matching.
  |
  |-- ml/
  |   |-- train_phishing.py
  |   |   Defines URLFeatureExtractor (sklearn BaseEstimator + TransformerMixin).
  |   |   Extracts 8 features from raw URL strings. Trains RandomForestClassifier
  |   |   inside a Pipeline. Saves phishing_model.joblib.
  |   |
  |   |-- train_invoice.py
  |   |   Generates synthetic invoice feature distribution (10,000 samples).
  |   |   Trains IsolationForest(n_estimators=100, contamination=0.10).
  |   |   Saves invoice_model.joblib.
  |   |
  |   |-- train_compliance.py
  |   |   Generates 5,000 synthetic compliance clause samples across 5 classes.
  |   |   Trains TF-IDF Vectorizer (ngram 1-2, max 5000 features) + Logistic
  |   |   Regression (balanced weights). Saves compliance_model.joblib.
  |   |
  |   |-- train_all.py
  |       Orchestrator script. Runs all three training scripts in sequence.
  |
  |-- models/
  |   |-- phishing_model.joblib    (105,250 bytes)
  |   |-- invoice_model.joblib     (873,545 bytes)
  |   |-- compliance_model.joblib   (29,748 bytes)
  |
  |-- tests/
      Python test suite using pytest and httpx TestClient.
